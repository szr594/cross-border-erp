# MS-07 认证服务迁移规格

状态：设计于 2026-11-15 确认；2026-11-16 完成本地迁移/回退、完整容器链路和 VMware 切换页面验收。遗留认证数据清理与多角色专项验收另行跟踪。

## 接口和认证规则

Identity Service 内部端口 8081，拥有独立数据库 cross_erp_identity、数据库账号及 Flyway 历史。
保持 docs/auth-spec.md 的四个接口、Cookie 名称和响应格式；Access Token 15 分钟、Refresh Token 7 天、失败 5 次锁定 15 分钟。
RS256 签名的 issuer 仍为 cross-border-erp，保留 sub、sid、roles，增加 kid；私钥从只读挂载文件读取，仅 identity 持有。网关和旧 backend 配置公钥，只允许 RS256，不按未验证的 alg 动态选择验证器。
初次切换统一退出登录，不迁移 refresh_sessions；原始刷新令牌不落库、不入日志。

## 数据迁移

维护窗口暂停认证写入，备份现有认证表与部署配置；通过受控离线工具导入用户、角色和关系，保留主键、Argon2id 哈希、账号状态和锁定数据。工具不得在日志输出哈希或密码。
目标库先由 Flyway 建表，再执行事务性数据导入；角色按 code 校验主键一致性，不能覆盖已存在的非空用户库。核验计数、关系完整性及自增序列后开放服务。
旧库业务 JPA 仍依赖 app_users：包括订单查询、订单导入、采购、收货、库存和打包。暂保留稳定 ID、显示字段、状态及现有业务所需角色的本地投影，禁止业务服务跨库查询 Identity。
旧密码和刷新会话清理必须晚于回退演练，使用单独审查的迁移。回退窗口内隔离保存旧认证数据，关闭旧认证 HTTP 入口和初始化入口，不能继续用旧库签发令牌。
当前不增加账号编辑能力；后续新增账号与角色变更功能时，必须先实现投影同步，避免新用户在业务库缺失。

## 并发与异常

登录按用户行串行累计失败次数；成功登录重置计数。锁定期间不得登录或刷新。
刷新与同用户登录/撤销遵循统一的用户行锁顺序，刷新会话再次读取并锁定后轮换；两个并发刷新不得创建两个有效后继会话。
已撤销令牌重放撤销该用户全部活跃刷新会话，撤销结果不能因业务异常回滚。
退出保持幂等；退出撤销 Refresh Token，既有 Access Token 最长仍有效 15 分钟，不承诺即时踢出。
Redis 故障仅降级网关限流，不影响数据库账号锁定规则。

## 切换与回退

先发布不承接流量的 Identity、数据库和密钥配置，执行迁移演练与独立测试。
维护窗口中迁移认证数据，同时切换网关认证精确路由、网关验签与旧后端验签。禁止留下混合签发窗口。
旧后端关闭 /api/auth/**，保留业务 API；其健康检查应改用独立可验证的探针，避免依赖旧认证入口。
失败时停止 Identity 认证写入，恢复旧路由、旧验签和受控备份，用户重新登录。维护窗口不允许账号变更或业务写入，避免覆盖新数据。

## 验收门槛

- 保留现有认证接口与角色字段契约，原业务负责人和审计显示不变。
- RS256 正确密钥通过；错误签名、错误 issuer、过期、HS256 令牌均 401。
- 登录、刷新、退出、me、锁定、停用和初始化均有测试。
- MySQL 8.4 并发失败累计与双刷新测试通过。
- 空库迁移、重复迁移拒绝、保留 ID、旧业务关联及回退演练通过。
- 本地 Compose 全链路验收后才准备虚拟机升级；MS-07 未通过全部门槛不得勾选完成。
