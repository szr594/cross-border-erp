# 订单模块规格

## 1. 目标与边界

订单模块管理外部销售订单，并为采购、收货、库存分配和打包提供统一业务入口。

MVP 数据链：

```text
销售渠道 -> 店铺 -> 销售订单 -> 订单商品
                         |-> 采购申请/采购分配
                         |-> 库存分配
                         |-> 打包记录
```

订单模块负责：

- 保存订单、客户、地址和商品的下单时快照。
- 提供订单工作台、详情、筛选和履约进度。
- 保存订单负责人快照并审计负责人变更。
- 按订单商品发起或撤回尚未转为正式采购的采购申请。
- 汇总采购、收货、库存和打包模块的只读结果。
- 处理订单取消和人工异常。

订单模块不直接修改库存、确认采购付款、确认收货或完成打包，也不使用一个可人工修改的统一字段表达全部履约状态。

## 2. 已确认决策

1. 第一阶段订单来源为虚构演示数据和公司自有 CSV 模板，不接入 Faire API。
2. 所有已登录员工暂时可以查看全部订单。
3. 只有 `OWNER` 角色可以取消订单。
4. 采购角色的任何接口响应均不得包含客户电话和完整地址；不能只依赖前端隐藏。
5. 核心业务数据不物理删除；取消、撤回和异常解决均保留记录。
6. 数据库时间使用 UTC，界面使用 Asia/Shanghai；金额保存最小货币单位和 ISO 4217 币种。
7. CSV 只使用虚构数据。模板 v1 已确认，具体限制见 `order-import-spec.md`。

## 3. MVP 功能

### 3.1 订单工作台

支持分页，以及按订单号、商品名称/SKU、店铺、负责人、外部状态、履约阶段和下单时间筛选。默认展示可处理订单，并优先显示临近发货期限和异常订单。

列表接口只返回履约所需摘要，不返回电话或完整地址。

### 3.2 订单详情

展示基本信息、负责人、商品快照、库存分配、采购覆盖、关联采购、包裹、打包摘要和业务事件。客户敏感字段按角色在后端裁剪。

### 3.3 负责人

- 新订单使用店铺当前负责人作为订单快照。
- 店铺负责人以后变化不改写历史订单。
- 负责人修改必须记录操作人、原负责人、新负责人、原因和时间。

### 3.4 采购申请

可按订单商品选择数量加入待采购。申请数量不得超过实时缺口：

```text
实时采购缺口 = 订单数量 - 有效库存分配 - 有效采购意图
```

采购申请只表达意图。正式采购中数量不能让订单提前进入“已齐货”。尚未转为正式采购分配的申请允许撤回；已转为正式采购后必须在采购模块处理。

### 3.5 齐货判断

`InventoryAllocation` 是齐货判断的唯一事实。每个需要履约的订单商品都满足以下条件时，订单才是“已齐货”：

```text
有效库存分配数量 >= 订单数量
```

### 3.6 取消与异常

- 订单取消仅限老板。
- 已取消订单不再允许申请采购或开始打包。
- 取消服务在同一事务中释放全部 `RESERVED` 库存分配并写入库存流水。
- 已转单采购、采购单和收货事实保留，不因销售订单取消而删除或回滚。
- 存在 `CONSUMED` 库存分配时禁止取消，返回待人工处理错误。
- 人工异常需要原因；解决异常需要处理结论，并保留完整事件。

## 4. 状态模型

外部订单状态保存标准化值和原始值。MVP 标准化值为：

`NEW`、`PROCESSING`、`PRE_TRANSIT`、`IN_TRANSIT`、`DELIVERED`、`CANCELED`、`UNKNOWN`。

ERP 履约阶段由业务事实动态计算：

| 阶段 | 中文名称 | 含义 |
| --- | --- | --- |
| `PENDING` | 待处理 | 尚未分配库存或发起采购 |
| `PARTIALLY_ALLOCATED` | 部分满足 | 已分配部分库存，仍有缺口 |
| `WAITING_PROCUREMENT` | 待采购 | 缺口已提交采购申请 |
| `PROCUREMENT_IN_PROGRESS` | 采购中 | 已形成有效采购意图 |
| `DOMESTIC_TRANSIT` | 国内运输中 | 关联采购已进入国内运输 |
| `PARTIALLY_RECEIVED` | 部分到货 | 已确认部分合格到货，仍未齐货 |
| `READY_FOR_PACKING` | 已齐货 | 所有有效商品均已分配足够库存 |
| `PACKING` | 打包中 | 已开始打包 |
| `PACKED` | 已打包 | 打包完成，等待后续发货 |
| `SHIPPED` | 已出库 | 已确认出库 |
| `COMPLETED` | 已完成 | 外部履约完成 |
| `EXCEPTION` | 异常 | 存在未解决业务异常 |
| `CANCELED` | 已取消 | 订单取消，停止正常履约 |

计算优先级为：已取消、异常、已完成、已出库、已打包、打包中、已齐货、部分到货、国内运输中、采购中、待采购、部分满足、待处理。

## 5. 权限和隐私

| 操作 | OWNER | OPERATIONS | PROCUREMENT | WAREHOUSE | PACKING |
| --- | --- | --- | --- | --- | --- |
| 查看全部订单 | 是 | 是 | 是 | 是 | 是 |
| 查看完整客户联系方式 | 是 | 是 | 否 | 履约需要时 | 履约需要时 |
| 修改负责人 | 是 | 否 | 否 | 否 | 否 |
| 发起/撤回采购申请 | 是 | 是 | 是 | 否 | 否 |
| 标记异常 | 是 | 是 | 是 | 是 | 是 |
| 取消订单 | 是 | 否 | 否 | 否 | 否 |

接口 DTO 必须使用字段白名单。采购角色响应不出现 `recipientPhone`、地址行、邮编等字段，也不能返回可还原这些字段的原始载荷。

## 6. CSV 建议模板 v1

模板 v1 已进入实现，每行代表一个订单商品：

```text
store_code,external_order_id,display_order_no,external_status,
ordered_at,requested_ship_at,currency,responsible_login,
customer_id,customer_name,recipient_name,recipient_phone,
country_code,province,city,district,address_line1,address_line2,postal_code,
external_item_id,external_product_id,external_variant_id,external_sku,
product_name,variant_name,image_url,quantity,unit_price_minor,note
```

导入按 `store + external_order_id` 幂等。预检返回逐行错误；已产生下游事实的订单禁止覆盖关键商品数量。

## 7. 验收标准

1. 同一店铺和外部订单号不能重复创建。
2. 工作台支持分页和组合筛选，列表不泄露客户敏感信息。
3. 订单商品保留下单时快照，不随商品主数据变化。
4. 履约阶段由后端事实计算，客户端不能提交阶段值。
5. 只有有效库存分配能使订单进入“已齐货”。
6. 采购申请不能超过事务内重新计算的缺口。
7. 负责人变更、取消、异常和采购申请均留下事件。
8. 只有老板能够取消订单。
9. 采购角色无法通过任何订单接口获得电话、完整地址或原始载荷。
10. 并发写操作使用乐观锁，冲突返回 HTTP 409。

## 8. 实施顺序与验证

| 步骤 | 输入 | 产出 | 依赖 | 主要风险 | 验证 |
| --- | --- | --- | --- | --- | --- |
| 1. 数据模型 | 本规格和数据库设计 | Flyway V2、实体和仓储 | 认证用户表 | 约束遗漏 | MySQL 兼容迁移与 H2 测试 |
| 2. 查询服务 | 订单、商品和角色 | 列表、详情、阶段投影 | 步骤1 | N+1、敏感字段泄露 | 查询集成测试、角色 DTO 测试 |
| 3. 命令服务 | 版本号和实时缺口 | 负责人、采购申请、异常、取消 | 步骤1 | 并发超量、越权 | 事务和并发测试 |
| 4. 演示与导入 | 虚构演示数据、模板 v1 | 幂等导入和错误报告 | 步骤1-3 | 覆盖下游事实 | 重复导入和失败行测试 |
| 5. 前端工作台 | 已批准 API | 列表、筛选和详情 | 步骤2-4 | 前端重复业务判断 | 类型检查、构建、关键路径验收 |

真实 Faire API、销售分析、成本利润、国际物流接口和复杂批量操作均不在本模块 MVP。
