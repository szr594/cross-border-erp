# 打包模块规格

## 1. 模块边界

打包模块承接库存已全部预留的销售订单，记录一个订单如何拆分到多个包装箱，并在确认完成时原子消耗对应的库存预留。第一阶段不处理国际物流、面单、运费、称重设备接入或完成后的冲销。

## 2. 核心规则

- 一个销售订单最多对应一个打包任务。
- 只有非取消、无履约异常且所有正常商品均已完整预留的订单可以开始打包。
- 一个任务可以包含多个包装箱；箱内商品必须绑定订单已有的库存分配。
- 同一库存分配可以拆到多个箱，但所有箱的合计不能超过预留数量。
- 完成时，订单商品装箱合计必须等于订单需求，分配装箱合计必须等于分配数量。
- 完成操作使用幂等键和乐观版本；重复提交同一完成命令返回原结果。
- 完成后任务、箱和箱内商品不可修改，第一阶段不支持撤销。
- 取消只适用于草稿任务，不释放库存预留；订单仍可在库存或订单流程中另行处理。

## 3. 状态

| 状态 | 含义 |
| --- | --- |
| `READY` | 查询态：订单已齐货但尚未创建任务 |
| `DRAFT` | 已开始，可新增、修改或删除包装箱 |
| `COMPLETED` | 已完成，库存预留已消耗，任务不可修改 |
| `CANCELED` | 草稿任务已取消，任务不可修改 |

订单履约阶段动态映射为 `READY_FOR_PACKING`、`PACKING` 和 `PACKED`，不在订单表冗余写入阶段字段。

## 4. 数据模型

- `packing_tasks`：订单唯一任务、状态、操作人、完成幂等键和乐观版本。
- `packing_boxes`：箱号、重量、长宽高和备注。
- `packing_box_items`：包装箱、销售订单商品、库存分配和数量。
- `packing_events`：开始、箱变更、完成和取消的操作轨迹。

数据库结构由 Flyway `V7__packing_schema.sql` 管理。

## 5. 权限

所有已登录员工可以查看打包工作台和详情。只有 `OWNER` 与 `PACKING` 可以开始任务、维护包装箱、完成或取消任务。后端权限校验是唯一可信边界。

## 6. 事务与并发

完成命令锁定打包任务，校验当前版本和完整装箱数量，再按库存批次 ID、库存分配 ID 的稳定顺序加行锁。库存余额、分配状态、库存流水、任务状态和完成事件在同一事务提交；任一步失败全部回滚。

## 7. 页面

- 打包工作台：待开始、打包中、已完成统计；订单号和状态筛选；任务列表。
- 打包详情：订单概览、库存预留、包装箱、箱内商品、操作事件。
- 草稿操作：新增/编辑/删除包装箱、完成、取消。
- 完成和取消任务只读展示，不提供修改入口。

## 8. 验收标准

1. 库存未完整预留时不能开始打包。
2. 箱内数量超过分配数量时拒绝保存。
3. 少装、漏装或重复装箱时不能完成。
4. 完成后所有相关分配变为 `CONSUMED`，批次预留减少、已消耗增加。
5. 每个分配生成且只生成一条对应幂等键的 `PACKING_CONSUMED` 流水。
6. 重复完成不会重复扣减库存或生成流水。
7. 非 `OWNER`、`PACKING` 角色不能执行写操作。
8. 工作台和详情不暴露客户电话或完整地址。
